# Pulso contracts

This directory contains the robot-independent boundary between Pulso's body and
brain. ROS, Android ARCore, recorded bags, and deterministic replays map into
these meanings.

- `pulso-observation-v1.schema.json`: one coherent observation envelope.
- `pulso-action-v1.schema.json`: one typed intent emitted by the brain.
- `pulso-brain-trace-v1.schema.json`: bounded public decision evidence tied to
  the exact Gemma turn and selected WorldPacket. It excludes model thoughts,
  skill bodies, and opaque candidate capabilities.
- `pulso-perception-telemetry-v1.schema.json`: detector health, backend/provider and timing;
  bounding boxes remain in the perception tracks stream.
- `pulso-gemma-input-v1.schema.json`: auditable runtime identity, exact
  message/order, system prompt, tool schemas, conversation scope and optional
  image metadata for each real LiteRT-LM turn. The exact JPEG bytes travel on
  `/pulso/hil/gemma_view/compressed`; private model channels never do.

The operator-only `pulso.metaview-scene.v1` JSON stream is generated by
`sim/ros2_ws/src/pulso_navigation/pulso_navigation/metaview_scene.py`. It is a
bounded 2.5D/3D visualization contract, not a brain/body command contract; its
stable topic and evidence rules are documented in
`docs/simulation/SENSOR_CONTRACT.md`.

Large RGB, depth, audio, map, and point-cloud payloads travel as referenced
artifacts or native transport streams. They are not embedded in the JSON
envelope and they are not serialized into Gemma's prompt.

The schemas are a transport-neutral HIL contract. Stable ROS topic mappings are
defined in `docs/simulation/SENSOR_CONTRACT.md`.
